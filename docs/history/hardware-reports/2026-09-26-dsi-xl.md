## Touch bug (fixed in dsi-test-2)

Buttons acted on the touch-down frame (`keysDown() & KEY_TOUCH`) and read the
position in that same frame. On real hardware that first reading is not
stable yet (typically 0,0), so taps missed every button; melonDS reports the
exact position immediately, which hid it. The diagnostics touch test worked
because it polls the position continuously while the stylus is down.

Fix: `nds_ui.TapTracker`, used by all touch UI: keeps the last valid position
while the stylus is down (ignoring 0,0) and fires the tap on release. The host
simulator now mimics the hardware (first reading 0,0), and with it the old
code fails the flow tests, so this is covered from now on.

## Retest with dsi-test-2 (same day)

Touch works on buttons and keyboards. Full flow on the real DSi XL, as in the
test guide: testnet via Settings, seed loaded by
scanning the test SeedQR with the camera (fingerprint 8b218e81), PSBT scanned
from the computer screen, review (Full Spend! warning, both recipients),
approve, signed PSBT shown as an animated QR. The developer build's check code
